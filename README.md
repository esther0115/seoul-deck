# Seoul Deck

打开就能用：https://esther0115.github.io/seoul-deck/

我自己去首尔前存了十几篇小红书攻略，真要出发还是得一家家翻帖子，判断值不值得去、一个人进不进得去、和别的店顺不顺路。Seoul Deck 把这一步交给 AI：它读中国游客的分享和 Kakao 地图上的韩文评价，整理出每家店的口碑，再按街区排成一天走得完的路线。走到一半下雨了、累了，可以用一句话让 AI 改剩下的安排。

第一次打开，可以先点页面上方「第一次来」里的四个按钮，分别看一天怎么排、评价怎么影响选店、AI 怎么临时改计划、AI 怎么读一篇攻略。

## AI 做什么，代码管什么

模型负责读懂人话。它从 226 篇小红书帖子和 5,817 条评论里抽出带原话的判断（值不值得、一个人能不能去、现场怎么样），写每家店的一句话总结，读 Kakao 韩文评价并翻译，路上听懂「走不动了」这类话并提出改法，把贴进来的攻略里的店对到店卡上。

代码负责把关。原话必须在原帖里逐字找得到；改计划时店必须在数据里、到店时开着门、不用久等，越界的请求直接拦下；分店对不上、把握不高的店不自动加，交给用户确认。差评明显多、附近又有条件相同口碑更好的店时，路线会默认换掉它，并在卡上写明为什么换。

## 我怎么检查它做得对不对

都是我自己建的评测集，不是用户数据。判读：我先盲标 70 句再看模型答案，7 个字段一致率 76% 到 96%，原话逐字 100%。召回：5 家店 74 段里该收的收进了 89%。改计划：27 句真实调用，听懂 20/20，越界拒答 4/4，违规 0。导入攻略：20 篇没参与调试的帖子，自动加进行程的 97 家里错加 0 家，召回 92%。改计划以后页面前后是否一致（说明、站数、导航有没有跟着变），回放的 12 句和 6 个街区的 114 种组合全部通过。

## 还没做到的

还没有真实用户，采用意愿、省下多少时间都没有数据。步行时间按直线距离加绕路系数估算，营业时间和人均是 2026 年 10 月下旬读的，出发前要再核对。这个网页版里的「一句话改计划」和「导入攻略」只能看录制回放；在 claude.ai 登录后打开 Claude 版页面可以实时用自己的 Claude 试：https://claude.ai/artifact/3wojQn5HkEuUWLcQZrd672

产品设计、判读规则、评测标注和每次取舍是我做的，代码用 Claude Code 写。这个仓库只放生成好的页面（`index.html`）和数据（`deck/`），数据流水线、提示词和评测记录在我本地的项目文件夹里。
